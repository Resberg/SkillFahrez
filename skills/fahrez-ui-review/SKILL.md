# Review a UI

Establish the intended user task and the surface under review. Inspect the implementation and rendered behavior before proposing changes. If visual tools are unavailable, label the work a source review and explain the limits.

Walk the main journey with pointer and keyboard. Inspect a wide and a narrow viewport, long labels/content, empty data, validation failure, and recovery where relevant. Check focus visibility/order, semantic controls, accessible names, text contrast, layout overflow, and whether important information relies on color alone.

Record each actionable issue with its location, observed behavior, user impact, and a specific correction. Rank blocked actions and inaccessible controls above decorative inconsistencies. Separate a subjective alternative from a demonstrated failure. Preserve a coherent existing identity.

When asked to fix, make focused changes and inspect the affected journey again. Check neighboring states for regressions. Run relevant project checks; avoid introducing dependencies or rewriting the design system for a local correction.

Deliver the highest-impact findings or fixes, the evidence gathered, and any untested areas. Do not certify universal accessibility from a few screenshots or an automated score.
